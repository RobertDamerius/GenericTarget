Simulink block

Write Bus To File

GenericTarget / Interface / Write Bus To File

Records an entire bus signal to one or more data files on the target computer. Each recorded sample consists of a time point obtained from the UTC Time block and the values of all signals in the bus at that point in time. The number of samples written per file is controlled by the numSamplesPerFile parameter; once this limit is reached, a new data file is opened automatically. Recorded files can be loaded into MATLAB as a structure of time tables using the GT.LoadDataFiles() function.

Input Ports

bus

The bus signal to be recorded. The bus may contain nested buses and built-in data types supported by the Simulink byte pack blocks, such as boolean, uint8, int8, uint16, int16, uint32, int32, single, double. All bus and signal names must be valid MATLAB variable names.

Block Parameters

The following table shows all block parameters.

Parameter NameDescription
strIDUnique identifier of this data recorder. The ID is also used as the base name of the data files (for example, myData_0, myData_1, and so on). It must be unique within the model.
numSamplesPerFileMaximum number of samples written to a single data file before a new file is opened automatically. A value of 0 disables file rotation, so that all samples are written to one file.
sampleCapacityLog2Exponent for the ring buffer capacity. The buffer holds 2^sampleCapacityLog2 samples. Valid range: [0, 16].
SampleTimeSample time of the block.

Further Notes

Bus Signal

Clicking the Update button in the block mask triggers an analysis of the input bus. For this purpose, the Simulink model is compiled once to determine the data types and dimensions of every signal; the model must therefore be error-free at that point. Based on the resulting structure, the block configures itself so that all signals of the bus are selected and serialized in a defined order.

Important

If the structure of the input bus changes, for example after adding or removing signals, the block must be updated again by clicking Update in the block mask. Otherwise, the recorded data no longer matches the actual bus content.

Unique ID

Every data recorder is identified by a unique ID configured in the block mask. This string is also used as the base name of the data files (for example, myData_0). An ID may occur only once within a model; if two blocks share the same ID, initialization of the target application fails.

Data Recording

The actual writing of recorded data to disk is performed by a dedicated non-realtime background thread; one such thread is created per recording ID. During real-time execution, each new sample is only written into an internal ring buffer (see Ring Buffer). When the number of written samples reaches the value of numSamplesPerFile, the background thread opens a new data file and continues writing there. Each recorded sample contains the UTC Time as well as all values of the bus at that point in time. During termination of the application, any samples still held in the buffer are flushed to the data files so that no recorded data is lost.

Ring Buffer

Each data recorder internally consists of a fixed-size ring buffer whose capacity is set by the sampleCapacityLog2 parameter: the buffer holds 2^sampleCapacityLog2 samples. The real-time execution path writes new samples into the ring buffer, while the non-realtime background thread reads them out and appends them to the current data file. If the ring buffer becomes full before the background thread has drained it, new samples overwrite the oldest ones; accordingly, data may be lost if the writer cannot keep up with the sample rate. After finishing a write operation, the background thread sleeps for 1 millisecond before checking the ring buffer again.
