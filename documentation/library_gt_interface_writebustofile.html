Simulink block

Write Bus To File

GenericTarget / Interface / Write Bus To File

Records a complete bus signal to a data file. The timestamp of each sample is taken from the model's digital clock. The maximum number of samples per file can be specified; a sample consists of the timestamp and the values of all signals in the bus at that sample time point.

Input Ports

bus

A bus signal. The bus may consist of nested buses and built-in data types supported by Simulink byte pack blocks, such as boolean, uint8, int8, uint16, int16, uint32, int32, single, double. All bus and signal names must be valid MATLAB variable names.

Block Parameters

The following table shows all block parameters.

Parameter NameDescription
strIDUnique ID for this data recording; it is used in the file names.
numSamplesPerFileMaximum number of samples per data recording file. A value of 0 disables file splitting.
writeFilesDuringSimulationEnables data recording during simulation in Simulink.
SampleTimeSample time of the block.

Further Notes

Bus Signal

When the Update button in the block mask is clicked, the input bus signal is analyzed: the Simulink model is compiled once to determine the data types and dimensions of all signals (the model must therefore be error-free). The block then configures itself to select and serialize all signals of the bus according to the reconstructed structure.

Important

If the structure of the bus is changed, this block must be updated again via the block mask.

Unique ID

Each recording is identified by a unique ID set in the block mask. The ID is a string that is also used in the names of the recording files. An ID may occur only once in the model; if an ID is duplicated, the initialization of the target application fails.

Data Recording

A dedicated non-realtime background thread takes over the actual writing of the data into the recording files; one thread is created per ID. The numSamplesPerFile parameter defines how many samples are written to a file before a new file is opened. Each sample contains the timestamp, which corresponds to the simulation time (digital clock), as well as all values of the bus at that sample time point. When the application terminates, any samples that are still buffered are written to the data files.

Write Files during Simulation

If the writeFilesDuringSimulation checkbox is enabled, data is also recorded during simulation in Simulink; a data directory is created in the current working directory. Note that a data directory is created whenever the initialization callback of the driver block is executed — this may also happen during a model compilation, for example when the Update button in the block mask is clicked.
