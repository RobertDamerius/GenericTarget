TCP Client Send

GenericTarget / Interface / TCP Client Send

Sends data to a connected TCP server. If the manageConnection checkbox is enabled, the server address and port can be controlled via the serverAddress and serverPort inputs of this block or of a TCP Client Receive block that shares the same local port.

Internally, the target application uses one socket per local TCP port, managed by a dedicated thread that handles socket creation and the connection to the server. If a TCP Client Send block and a TCP Client Receive block share the same local port, they access the same socket in the background. Their mask settings must therefore be identical; otherwise, the initialization phase of the target application fails.

A local port value less than 1 can also be selected in the block mask; in that case, the operating system assigns the actual TCP port randomly. All TCP Client Send and Receive blocks that share the same local port value must nevertheless have identical mask settings: for example, several blocks with the local port -3 share a single background socket whose port is assigned randomly by the operating system.

Input Ports

serverAddress

A vector of 4 elements indicating the IPv4 address of the server. A zero address, e.g., [0,0,0,0], disconnects the client from the server. This input is ignored if the manageConnection checkbox is disabled.

Data Type: uint8

serverPort

The port of the server. A value of 0 disconnects the client from the server. This input is ignored if the manageConnection checkbox is disabled.

Data Type: uint16

bytes

A vector containing the data to be sent.

Data Type: uint8

length

The number of bytes to send.

Data Type: int32

Output Ports

numBytesSent

The number of bytes that were sent, or a negative value in case of an error. Since TCP is a byte stream, this can be smaller than length if the socket buffer cannot accept all bytes right away.

Data Type: int32

details

This output port is available when the Show details output port option is enabled in the block mask.

Data Type: Bus

The bus contains the following values:

Parameter NameData TypeDescription
resultint32Result of the socket send function call: the number of bytes that have been sent, or a negative value in case of errors.
lastErrorCodeint32The last socket error code from sending a message. 0 means no error. The actual meaning of non-zero values depends on the operating system.
isConnectedbooleanThe latest connection state to the server.

Further Notes

Socket

A socket is the interface between an application and the network. The TCP client socket is created when connecting to the server and destroyed when the connection is closed. Socket creation, connection handling, and reconnection are performed in a dedicated non-real-time background thread. After socket creation, the socket option SO_REUSEADDR is enabled, which allows the local port to be bound again while an earlier connection from that port is still lingering (for example in the TIME_WAIT state).

Port Range

Port numbers are commonly categorized as follows:

  • System Ports (1–1023): reserved for system processes and should not be used.
  • User Ports (1024–49151): available for general use.
  • Dynamic Ports (49152–65535): typically assigned dynamically, but availability may vary depending on the operating system.

Ports in the dynamic range may be restricted by the operating system. If a port cannot be bound, it is either already in use or blocked by system policies. Setting the local port to a value below 1 in the block mask lets the Generic Target request a random local port, usually from the dynamic range.

Socket Options

The socket options below are applied when the socket is created, before the connection is established. The option names are the setsockopt() constants of the Linux API.

  • deviceName — SO_BINDTODEVICE (Linux only). Binds the socket to a specific network device before the socket is bound to its local port, so that the traffic is guaranteed to use the selected interface. The device name must not be longer than 15 characters. If the device does not exist yet, the connection attempts are retried by the background thread until it becomes available.
  • socketPriority — SO_PRIORITY (Linux only). Sets the socket priority used by the network queue management of the kernel, so that higher-priority traffic is scheduled first according to the active queuing discipline. The value must be between 0 and 6; values above 6 require the CAP_NET_ADMIN or CAP_NET_RAW capability.
  • typeOfService — IP_TOS (Linux only). Sets the type-of-service (DSCP) byte of the outgoing IP packets, for example 0xB8 for DSCP 46 (expedited forwarding). A value of 0 keeps the system default.
  • noDelay — TCP_NODELAY. Disables Nagle's algorithm so that small segments are sent at once instead of being coalesced. This is essential for low-latency communication and is enabled by default.
  • kernelSendBufferSize — SO_SNDBUF, kernelReceiveBufferSize — SO_RCVBUF. Request the size of the kernel send and receive buffers in bytes. The kernel doubles the requested value. A value of 0 keeps the auto-tuned system default. The buffers are set before the connection is established, because they influence what the connection negotiates.
  • keepAlive — SO_KEEPALIVE. Enables keep-alive probing of an idle connection, which detects a server that vanished without a trace (cable pulled, power loss). Enabled by default.
  • keepAliveIdle — TCP_KEEPIDLE, keepAliveInterval — TCP_KEEPINTVL, keepAliveCount — TCP_KEEPCNT (Linux only). Control the timing of the keep-alive probes: the number of seconds without traffic until the first probe is sent, the number of seconds between two probes, and the number of unanswered probes until the connection is dropped. All values must be at least 1.
  • userTimeout — TCP_USER_TIMEOUT (Linux only). Limits the time that sent data or a keep-alive probe may stay unacknowledged, in milliseconds, until the connection is dropped. A non-zero value overrides TCP_KEEPCNT. A value of 0 keeps the system default.

Connection Management

A dedicated thread is started for every TCP socket. This thread manages the entire connection lifecycle: socket initialization, port binding, establishment of the TCP connection to the remote server, monitoring of the connection, and automatic reconnection attempts. As long as the server cannot be reached or the connection is lost, the thread retries the connection once per second. A connection attempt that is not finished after 5 seconds is aborted and retried. The server address and port are supplied as inputs to the TCP Client blocks; they can be set by both the Send and the Receive block of a socket. A disconnection is requested by setting the server address to [0,0,0,0] or the server port to 0. If a block should not participate in connection management and should ignore its server address and port inputs, disable the manageConnection checkbox in its mask.

Error Codes

On Linux, lastErrorCode contains the errno value of the failed socket operation (on Windows, the corresponding Winsock error code). While no connection is established, typical values are EINPROGRESS (a connection attempt is in progress), ECONNREFUSED (the server refused the connection), and ENOTCONN (the connection is closed, for example after a disconnect request). During normal operation, EAGAIN indicates that a non-blocking send or receive had nothing to transfer at that moment.
