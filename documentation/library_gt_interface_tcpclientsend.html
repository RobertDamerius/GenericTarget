Simulink block

TCP Client Send

GenericTarget / Interface / TCP Client Send

Sends data to a connected TCP server. If the manageConnection checkbox is enabled, the server address and port can be controlled via the serverAddress and serverPort inputs of this block or of a TCP Client Receive block that shares the same local port.

Internally, the target application uses one socket per local TCP port, managed by a dedicated thread that handles socket creation and the connection to the server. If a TCP Client Send block and a TCP Client Receive block share the same local port, they access the same socket in the background. Their mask settings must therefore be identical; otherwise, the initialization phase of the target application fails.

A local port value less than 1 can also be selected in the block mask; in that case, the operating system assigns the actual TCP port randomly. All TCP Client Send and Receive blocks that share the same local port value must nevertheless have identical mask settings: for example, several blocks with the local port -3 share a single background socket whose port is assigned randomly by the operating system.

Input Ports

serverAddress

A vector of 4 elements indicating the IPv4 address of the server. A zero address, e.g., [0,0,0,0], disconnects the client from the server. This input is ignored if the manageConnection checkbox is disabled.

Data Type: uint8

serverPort

The port of the server. A value of 0 disconnects the client from the server. This input is ignored if the manageConnection checkbox is disabled.

Data Type: uint16

bytes

A vector containing the data to be sent.

Data Type: uint8

length

The number of bytes to send.

Data Type: int32

Output Ports

numBytesSent

The number of bytes that were sent, or 0 in case of an error.

Data Type: int32

details

This output port is available when the Show details output port option is enabled in the block mask.

Data Type: Bus

The bus contains the following values:

Parameter NameData TypeDescription
resultint32Result of the socket send function call: the number of bytes that have been sent, or a negative value in case of errors.
lastErrorCodeint32The last socket error code from sending a message. 0 means no error. The actual meaning of non-zero values depends on the operating system.
isConnectedbooleanThe latest connection state to the server.

Block Parameters

The following table shows all block parameters.

Parameter NameDescription
showDetailsEnables the details output port.

Further Notes

Socket

A socket is the interface between an application and the network. The TCP client socket is created when connecting to the server and destroyed when the connection is closed. Socket creation and connection handling are performed in a dedicated thread that runs with priority 21. The socket options SO_REUSEPORT and SO_REUSEADDR are enabled after socket creation, which allows multiple sockets (for example, multiple blocks) to bind to the same port and device.

Port Range

Port numbers are commonly categorized as follows:

  • System Ports (1–1023): reserved for system processes and should not be used.
  • User Ports (1024–49151): available for general use.
  • Dynamic Ports (49152–65536): typically assigned dynamically, but availability may vary depending on the operating system.

Ports in the dynamic range may be restricted by the operating system. If a port cannot be bound, it is either already in use or blocked by system policies. Setting the local port to a value below 1 in the block mask lets the Generic Target request a random local port, usually from the dynamic range.

Socket Priority

This value must be between 0 and 6. It sets the IP type-of-service priority for the packets of this socket; Linux uses this value in its network queue management, so that higher-priority traffic is scheduled first according to the active queuing discipline.

Connection Management

A dedicated thread is started for every TCP socket. This thread manages the entire connection lifecycle: socket initialization, port binding, establishment of the TCP connection to the remote server, and automatic reconnection attempts. The server address and port are supplied as inputs to the TCP Client blocks; they can be set by both the Send and the Receive block of a socket. A disconnection is requested by setting the server address to [0,0,0,0] or the server port to 0. If a block should not participate in connection management and should ignore its server address and port inputs, disable the manageConnection checkbox in its mask.
