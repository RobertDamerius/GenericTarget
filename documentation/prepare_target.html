Prepare the Target Computer

Before using the Generic Target Toolbox, the target computer must run a Linux-based operating system. Any distribution is supported, but Debian is recommended: it is widely maintained and provides the real-time kernel as a standard package. Because setup steps vary between distributions, the instructions below target Debian specifically; users of other distributions may need to adapt them. In addition, SSH key authentication must be configured so that the host computer can log in to the target without an interactive password prompt. The steps are outlined in the list below.

  • Step 1: Install Debian
  • Step 2: Configure Debian
  • Step 3: Configure passwordless SSH authentication
  • Step 4: Optional hardware tuning and advanced options

Step 1: Install Debian

To set up the target computer:

  1. Download the Debian ISO image from www.debian.org.
  2. Create a bootable USB stick using the ISO image and boot the target computer from it.
  3. Follow the installation instructions, selecting the minimal installation option if available to keep the system lightweight.
  4. Enable the SSH server during the installation process; it is required for all automated deployment commands.

Note

A desktop environment (GUI) is not required for the Generic Target Toolbox. You may install one if you prefer, but it is not necessary for functionality.

Step 2: Configure Debian

After the operating system is installed, the required dependencies are installed and the system settings are configured. The following two commands, executed in sequence, complete the full setup automatically.

Command 1

Open a terminal and run the following command:

su -l -c "export PATH=$PATH:/sbin:/usr/sbin:/usr/local/sbin && adduser $USER sudo && echo "$USER ALL=(ALL) NOPASSWD: ALL" > ~/$USER-nopasswd && chown root:root ~/$USER-nopasswd && mv ~/$USER-nopasswd /etc/sudoers.d/ && echo 'APT::Get::Always-Include-Phased-Updates "1";' >> /etc/apt/apt.conf.d/99always-include-phased-updates && reboot"

This command:

  • adds /sbin, /usr/sbin, and /usr/local/sbin to the PATH
  • adds the current user to the sudo group
  • installs a sudoers rule that allows passwordless sudo for the current user
  • disables APT phased updates
  • reboots the target computer

Command 2

Open a terminal and run the following command:

sudo apt update && sudo apt -y upgrade && sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target && echo -e "net.core.rmem_max=33554432\nnet.core.wmem_max=33554432" | sudo tee /etc/sysctl.d/99-custom-buffers.conf && sudo sysctl --system && sudo apt -y install linux-image-rt-amd64 g++ gdb make build-essential net-tools btop && sudo reboot

This command:

  • updates all installed packages
  • masks the system sleep, suspend, and hibernate targets to disable energy-saving standby modes
  • increases the kernel network receive/send buffer limits to 32 MiB (net.core.rmem_max, net.core.wmem_max)
  • installs the PREEMPT_RT real-time kernel
  • installs the C++ compiler, debugger, and build tools: g++, gdb, make, build-essential, net-tools, btop
  • reboots the target computer

After the reboot, verify that the real-time kernel is active by running uname -a in a terminal. The output should contain SMP PREEMPT_RT.

Important — Compiler requirements

A g++ compiler of version 13 or newer is required to build the target application, and it must support the C++20 standard. Check the installed compiler version with g++ --version. To verify C++20 support, run g++ -std=c++20 -x c++ -fsyntax-only /dev/null; the command should complete without printing an error message.

Step 3: Configure Passwordless SSH Authentication

Important

On a Linux host this step is recommended. On a Windows host it is required, since ssh/scp commands executed from the MATLAB console cannot answer an interactive password prompt.

When creating, starting, or stopping an application on the target computer with the Generic Target Toolbox, commands are executed over SSH. By default, every SSH connection requires an interactive password confirmation, which interrupts the automated deployment. By exchanging an SSH key pair once, passwordless authentication between the host computer and the target is established. The keys are stored in the ~/.ssh/ directory of the user's home folder; deleting this directory removes all stored keys and known hosts.

Unless stated otherwise, the commands below are executed on the host computer (the SSH client), which connects to the SSH server running on the target computer.

Linux host

The following description applies only to Linux host computers, since some commands are not available on Windows.

1. Generate the key.

The command ssh-keygen generates an SSH key pair. You can specify the file under which the key is stored; pressing RETURN accepts the default location. You are then asked for a passphrase that protects the private key; pressing RETURN uses an empty passphrase. The same key can be used for several target computers — when setting up additional targets, start with step 2.

2. Copy the public key to the target.

To copy the generated public key to a target computer, use the command:

ssh-copy-id -i ~/.ssh/id_ed25519.pub UserName@RemoteServer

Replace UserName with the user name on the target and RemoteServer with its IP address (or host name).

3. Add the private key.

All that remains is to add the private key:

ssh-add

SSH connections should now be established without a password prompt. Verify this with ssh UserName@RemoteServer.

Windows host

1. Prepare.

Open PowerShell as an administrator and run:

Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0

This installs the OpenSSH client. Close the elevated PowerShell; the remaining commands can be executed in a regular Windows terminal.

2. Generate the key.

The command ssh-keygen generates an SSH key pair. You can specify the file under which the key is stored; pressing RETURN accepts the default location. You are then asked for a passphrase that protects the private key; pressing RETURN uses an empty passphrase. It is recommended to leave the passphrase empty, since a passphrase prompt would interrupt the automated deployment process. The same key can be used for several target computers — when setting up additional targets, start with step 3.

3. Copy the public key to the target.

To copy the generated public key to a target computer, use the command:

scp C:\Users\HostName\.ssh\id_ed25519.pub UserName@RemoteServer:

Here HostName is your user name on the host, and UserName and RemoteServer are the user name and IP address of the target computer, respectively. Note the trailing : character, which uploads the file into the user's home directory on the target.

4. Configure the key.

Log in to the target computer via SSH using:

ssh UserName@RemoteServer

The following commands are all executed on the target computer. First, make sure the .ssh directory exists; create it if it does not:

mkdir .ssh

Append the uploaded public key to the authorized keys:

cat id_ed25519.pub >> .ssh/authorized_keys

and delete the public key:

rm id_ed25519.pub

SSH enforces strict permissions on the .ssh directory and the authorized_keys file; set them explicitly: 

chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

Log out with:

exit

For testing, make an SSH connection from the host PC to the target computer with ssh UserName@RemoteServer.

Step 4: Optional Hardware Tuning and Advanced Options

Optional adjustments to the BIOS and the operating system can further improve performance and reduce the worst-case latency. The following recommendations are a good starting point.

In the BIOS, you may modify the following:

  • Enable Turbo Boost if the system supports it, to increase the available clock frequency.
  • Disable CPU C-states (the CPU power-saving sleep states).
  • Disable Hyper-Threading to avoid shared virtual CPU cores.

Update the GRUB bootloader menu

The GRUB configuration can be adjusted to reduce the bootloader timeout, which by default can delay every boot by several seconds. To modify the configuration, open the GRUB defaults file with the nano editor: 

sudo nano /etc/default/grub

After the changes, regenerate the bootloader configuration with:

sudo update-grub

The exact boot options available depend on the GRUB version and the distribution.

Isolating CPU cores

The target application can be pinned to specific CPU cores (see targetBitmaskCPUCores). CPU cores can additionally be isolated via the GRUB isolcpus option, which prevents the general-purpose scheduler from placing operating system processes on those cores. This allows the operating system to be restricted to certain cores while others are dedicated to the real-time application. For example, on an 8-core system, cores 0 and 1 can be left to the operating system while cores 2 to 7 are isolated: 

GRUB_CMDLINE_LINUX_DEFAULT="isolcpus=2-7"

After any change to the GRUB configuration, run sudo update-grub and reboot the target for the changes to take effect.
