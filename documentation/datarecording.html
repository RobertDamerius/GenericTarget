Data Recording

Data recording is performed with one of two blocks. The Write Scalar Doubles To File block records buses whose signals and sub-signals are all scalar values of data type double. If a bus contains multi-dimensional signals or data types other than double, the Write Bus To File block must be used instead; in that case the bus structure must be defined in advance.

Recorded data is written to files automatically: each sample is first written to an internal buffer, and a dedicated recording thread transfers the buffered samples to the data files. Every data recorder object is identified by a unique ID, which is also used in the names of the recording files.

Initialization

During initialization of the Simulink model, a new data directory is created whose name encodes the start time in UTC. In addition, an index file is written that contains metadata about the recording and lists all recording IDs; if the model contains multiple data recorder blocks, the index file is updated accordingly.

Termination

During the termination phase, any samples that are still buffered are flushed to the data files, so that no recorded data is lost.

Separate Data Recording Thread

The dedicated recording thread of each data recorder object is responsible for writing the buffered samples to the data files; its priority is set via the threadPriority parameter in the block mask. When the number of written samples exceeds the numSamplesPerFile parameter set in the mask of the corresponding Write To File block, the thread automatically opens a new data file and continues writing there.

File Format

Separate data files are created for each recording ID. For an ID of myData, the first data file is named myData_0. When the number of written samples exceeds the numSamplesPerFile parameter, a new data file myData_1 is created, and subsequent files are named myData_2, myData_3, and so on.

Each file contains its own header and can therefore be decoded independently of the other files. The header describes the recording, including the number of signals, the signal names, and the byte order; all recorded samples are appended after the header. The size of a file is determined by the numSamplesPerFile parameter. If this parameter is zero, no file splitting takes place and a single data file is written, e.g., myData_0.

The Doubles Data File (bus of scalar doubles)

The naming of a data file is ID_M where ID denotes the unique ID of the data recorder and M indicates the file number in ascending order. Each ID file contains a header to allow a single ID file to be decoded separately. The header data of all ID data files for an ID are identical. The actual sample data is appended after the header bytes.

Offset (Bytes)Length (Bytes)NameData TypeDescription
05header5 x uint8_tHeader identifier: contains the string "GTDBL" (0x47 0x54 0x44 0x42 0x4C).
54offsetSampleDatauint32_tThe zero-based offset to SampleData.
94numSignalsuint32_tThe number of signals in the bus to be recorded.
13LlabelsL x charString specifying the signal names. All signals are separated by commas, e.g., "value,nestedBus.value".
13+L1zeroTerminatoruint8_tZero-terminator for the preceding string. This value is always 0x00 and indicates the end of the string.
14+L1endianuint8_tSpecifies the byte order. 0x01: little endian, 0x80: big endian. This byte order is used for all subsequent values.
15+LSampleDataContains 1 + numSignals values of type double. Each sample data contains one double, which specifies the timestamp, followed by numSignals values of type double that indicate the bus signal data.

The Bus Data File (complete bus object)

The naming of a data file is ID_M where ID denotes the unique ID of the data recorder and M indicates the file number in ascending order. Each ID file contains a header to allow a single ID file to be decoded separately. The header data of all ID data files for an ID are identical. The actual sample data is appended after the header bytes.

05header5 x uint8_tHeader identifier: contains the string "GTBUS" (0x47 0x54 0x42 0x55 0x53).
54offsetSampleDatauint32_tThe zero-based offset to SampleData.
94numBytesPerSampleuint32_tThe number of bytes per sample excluding the 8-byte timestamp.
13LlabelsL x charString specifying the signal names. All signals are separated by commas, e.g., "value,nestedBus.value".

Each sample data contains one double at the beginning (first 8 bytes), which specifies the timestamp, followed by numBytesPerSample bytes that indicate the bus signal data. Dimension and data type are given by the two strings dimensions and dataTypes.
