TCP Client Send

Library

GenericTarget / Interface / TCP Client Send

Description

Send data to a connected TCP server. The server address is set via the server input of a TCP Client Send or TCP Client Receive block if the manageConnection checkbox is enabled. For each local TCP port, a separate thread is started, that manages socket creation and connection handling to the server. Internally, the target application uses one socket for equal TCP ports. If the same local port is set in a TCP Client Send and Receive block, both blocks access the same socket in the background. For this reason, the settings in the masks of the corresponding TCP Client Send and Receive blocks must be identical, otherwise the initialization phase of the target application will fail. Values less than 1 can also be selected for the port in the block mask. In this case, the actual TCP port is selected randomly by the operating system. Nevertheless, all TCP Client Send and Receive blocks with the same value in the local port must have the identical mask settings. If, for example, several TCP Client blocks have the local port -3, one common socket is used in the background whose current TCP port is randomly assigned by the operating system.

Input Ports

serverAddress

A 4-dimensional vector indicating the IPv4 address of the server. A zero-value address, e.g. [0,0,0,0], disconnects the client from the server. This input is ignored, if the checkbox manageConnection is disabled.
Data Type: uint8

serverPort

The server port. A value of 0 disconnects the client from the server. This input is ignored, if the checkbox manageConnection is disabled.
Data Type: uint16

bytes

A vector containing the data that should be sent.
Data Type: uint8

length

The number of bytes that should be sent.
Data Type: int32

Output Ports

numBytesSent

The number of bytes that have been sent or zero in case of errors.
Data Type: int32

details

This output port is enabled, when checking the option Show details output port via the block mask.
Data Type: Bus

The bus contains the following values.
Parameter NameData TypeDescription
resultint32Result of the socket send function call: The number of bytes that have been sent or a negative value in case of errors.
lastErrorCodeint32The last socket error code from sending a message. 0 means no error. The actual meaning of non-zero values depend on the operating system.
isConnectedbooleanThe latest connection state to the server.

Further Notes

Socket

A socket serves as the interface between an application and network hardware. The TCP client socket is created when connecting to a TCP server and is destroyed when disconnecting from the server. The whole socket creation and connection handling is done in a separate thread that runs with priority 21. The socket options SO_REUSEPORT and SO_REUSEADDR are enabled after socket creation, allowing multiple sockets (e.g., multiple blocks) to bind to the same port and device.

Port Range

Port numbers are usually categorized as follows:
  • System Ports (1–1023): Reserved for system processes and should not be used.
  • User Ports (1024–49151): Available for general use.
  • Dynamic Ports (49152–65536): Typically assigned dynamically, but availability may vary depending on the operating system.
In some cases, ports in the dynamic range may be restricted by the operating system. If a port cannot be bound, it may already be in use or blocked by system policies. Setting the local port to a value below 1 in the block mask allows the Generic Target to request a random local port, usually within the dynamic range.

Socket Priority

This value must be between 0 and 6 and determines the protocol-defined priority for outgoing packets. Linux uses this setting to manage networking queues, ensuring that higher-priority packets are processed first based on the selected queuing discipline.

Connection Management

For every TCP socket, a dedicated thread is instantiated. This thread is responsible for the entire connection lifecycle, including socket initialization, port binding, establishing the TCP connection to the remote server and managing automatic reconnection attempts. The necessary server address and port must be supplied as inputs to the TCP Client blocks. A request to disconnect is signaled by setting either the server address to 0.0.0.0 or the server port to 0. When valid (non-zero) server address and port are provided, the dedicated thread manages the full connection establishment sequence. The server address and port might be set by both the TCP Client Send and TCP Client Receive blocks. If a specific block should bypass connection management and ignore the server address and port inputs, disable the corresponding connection management checkbox within the block mask.
